# Skills 分类与自动发现的第二轮根因修复

2026-11-01，北京时间。取代此前把单项 Skill 作为并列目录的产品结构。

## 用户要求

只保留一个项目榜。Skills 是其中一个类型：单项技能仓库、含多个技能的仓库均可进入；具体技能显示在所属仓库下面，每个仓库仅按自己的总 Star 排名一次。不要求用户逐个提供漏收仓库。

## 为什么持续漏收

前一轮解决了合法 SKILL.md 的解析和父库漏标，却没有解决发现广度和扫描覆盖：仅三个 Topic 的第一页各100条；无关键词、名称和 README 发现；候选384只尝试18；全局700正文读取被大库占据。无效文件不缓存，单库2000文件上限没有断点。失败库只有检查时间，没有文件/子树游标。统计把本轮完成数当作累计覆盖，造成错误观感。

## 实际修复

1. 通过可配置的 Topic、仓库名、说明、README（SKILL.md、agentskills.io）自动发现候选。仓库种子用于启动，不是收录白名单，更没有单项 Skill 名单。
2. 每条搜索每页100条，超过GitHub单搜索1000条限制时，按互不重叠的创建时间范围二分，可细分至秒。持久化未完成查询、分片和下一页；失败、不完整结果保持待完成。当前查询组完成也不代表GitHub全站完成。
3. GraphQL批量核对仓库ID、默认分支、固定提交、Star和元数据；文件树用REST，正文用固定提交的公开raw地址，减少核心API消耗。GraphQL不可用可逐库回退，所有失败保留旧观测。
4. 各库先获得公平正文额度，多轮继续；缓存树清单、有效记录和无效文件的blob SHA。文件预算只限制本轮工作，旧文件不再反复占额，超出部分可续扫。递归树截断后的子树队列也保存断点。
5. 初次重扫优先处理原候选队列。核心配额不足就保存未完成状态，已有完整树的库仍可继续解析正文；后续采集自动接续。
6. 搜索结果只是候选。扫描合法文件后才确认Skills类型；已完成且无合法文件与未扫描/失败分开处理。候选不会因名字或Topic就被当作确认的Skill库。
7. 累计显示候选、已检查、已完成、待完成和失败数。文件记录按仓库ID+路径去重，与仓库计数和Star保持独立。
8. 移除独立Skill目录。技能嵌套在仓库行和仓库详情下，搜索技能名能找到并展开所属仓库。历史快照不注入未来扫描，但新快照会保存当时的多类型结果。

## 验证与运行

真实重扫由GitHub Actions执行，使用仓库已有GITHUB_TOKEN，不引入GPT运行依赖或访客登录。工作流保留每三天更新；本次代码发布触发一次重扫。运行完成后须检查生成的collection-status.json、最新数据、Action结果和网页，才能报告实际新增数量。

新增回归覆盖分页、1000条分片、断点、未完成搜索、身份核对、raw限额、文件断点、无效文件缓存、子树断点、公平多轮、累计覆盖、分类验证、技能名搜索和历史隔离。

## 明确的边界

GitHub仓库搜索无法列出所有含SKILL.md的仓库：没有任何可检索信号的仓库仍可能遗漏。搜索范围、API配额和待扫队列公开，不再用“已收录”冒充全站完整。skills.sh安装统计未接入，绝不使用仓库Star代替。
