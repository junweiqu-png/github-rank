# 项目类型与单项 Skill 目录的一致性核查

2026-11-01，北京时间。

用户看到两个入口里的 Skill 不一致。粒度差别只能解释一部分：项目榜每项是仓库，单项目录每项是合法 SKILL.md 文件。根因还包括真实的类型漏标。

## 复现和证据

修复前线上最新观测有 982 个仓库，306 个主类型为 skills；技能目录有 717 份文件记录，来自 16 个仓库。其中 10 个父仓库（对应 611 份记录）仍只归为 projects，包括 obra/superpowers、addyosmani/agent-skills 等。这些仓库在全部项目中存在，在 Skills 类型筛选中消失。

收集器保留先前的 category，Topic 发现不覆盖旧类型；Skill 扫描结果没有反馈给项目视图。原 ranking.js 只做 category 严格相等，app.js 的技能关联也只用于说明文本。因此目录发现成功，并不能保证父仓库进入对应筛选。

最小复现 `node --test test/skill-related.test.mjs` 在修复前失败：具有已发现技能的 projects 仓库，在 skills 筛选中返回空列表。仓库改名后的 ID 关联也未受支持。

## 修复

- 仓库保留主类型；使用仓库 ID 关联当前技能目录，已有 Skill 的仓库同时属于 Skill 相关仓库。
- 项目榜全部类型中每个仓库仍只计一次；skills 筛选与应用、插件等筛选可重叠。
- 标签明确为“Skill 相关仓库”，包含技能发布库、合集和相关工具，不暗示每行就是单个 Skill。
- 项目行显示实际已收录数量及“展开”入口；单项目录可按父仓库限定，并返回父仓库详情。
- 以仓库 ID 关联，避免重命名失联或旧名称被复用导致误关联。
- 未扫描或未完成的仓库不填造技能数；无展开入口不代表没有技能。
- 当前目录不会回填历史仓库分类，避免未来信息进入过去快照。

安装次数仍未接入，Star 和 Skill 安装量保持独立。每三天自动采集的规则不变；本次页面修复发布复用已采集数据。

## 验证

新增回归覆盖：同一仓库可属于多个相关类型而不重复计数；目录到仓库的真实关联参与筛选；历史模式不引入当前扫描；改名跟随 ID，复用名称不混入。原有排名、时区、发现、预算、失败保留、安装量缺失值等测试同时执行。
